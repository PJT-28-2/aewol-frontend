# QR 결제 페이로드 규약 및 시연 가이드

`/payment/qr` 화면에서 쓰는 QR의 형식과, 시연에 필요한 QR 이미지·진행 순서를 정리한 문서다.

---

## 1. 페이로드 규약

```
aewol://pay?merchant=<URL 인코딩된 가맹점명>&amount=<정수 원화>
```

예시 — 애월동물병원 3,300원

```
aewol://pay?merchant=%EC%95%A0%EC%9B%94%EB%8F%99%EB%AC%BC%EB%B3%91%EC%9B%90&amount=3300
```

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `merchant` | O | 가맹점명. **한글은 반드시 URL 인코딩한다.** 최대 100자 (백엔드 `transaction.merchant_name`이 VARCHAR(100)) |
| `amount` | O | 결제 금액. 원 단위 **정수만** 허용. 1 이상 10,000,000 이하 |

### 자주 하는 실수

**한글을 인코딩하지 않는 것이 가장 흔한 실수다.** 온라인 QR 생성기에
`aewol://pay?merchant=애월동물병원&amount=3300`을 그대로 붙여넣으면 생성기나 브라우저에 따라
인코딩 결과가 달라져 가맹점명이 깨진 채로 결제될 수 있다. 아래 3절의 방법으로 만들면
이 문제가 생기지 않는다.

### 거절되는 페이로드

파싱은 `src/utils/qr.js`의 `parseQrPayment()`가 담당하며, 아래는 모두 사용자에게 안내를 띄우고
결제로 넘어가지 않는다.

| 사유 | 예시 |
|---|---|
| 애월 QR이 아님 | `https://example.com` |
| 필수 파라미터 누락 | `aewol://pay?merchant=애월동물병원` |
| 가맹점명이 비었거나 100자 초과 | `aewol://pay?merchant=&amount=3300` |
| 금액이 정수가 아님 | `amount=30.5`, `amount=1e3`, `amount=-100` |
| 금액이 범위 밖 | `amount=0`, `amount=10000001` |

## 2. 시연용 QR 이미지

`docs/demo/`에 3장이 있다.

| 파일 | 페이로드 | 기대 동작 |
|---|---|---|
| `qr-payment-normal.png` | 애월동물병원 3,300원 | 확인 화면 → 결제 성공 → 잔액 차감 |
| `qr-payment-insufficient.png` | 애월동물병원 1,500,000원 | 결제 버튼 잠김 + "충전하러 가기" 노출 |
| `qr-payment-invalid.png` | `https://example.com` | "애월 결제 QR이 아니에요" 안내 |

> **잔액 부족 QR 주의** — 시연 계정 잔액이 1,500,000원을 넘으면 이 QR은 결제가 성공해버려서
> 의도한 화면이 나오지 않는다. 시연 전 잔액을 확인하고, 필요하면 3절 방법으로 더 큰 금액의
> QR을 다시 만든다.

---

## 3. QR 새로 만드는 법

### 방법 A — 페이로드 문자열을 코드로 만든다 (권장)

`src/utils/qr.js`의 `buildQrPayment()`가 URL 인코딩까지 처리한다.

```js
import { buildQrPayment } from '@/utils/qr'

buildQrPayment({ merchantName: '애월동물병원', amount: 3300 })
// → 'aewol://pay?merchant=%EC%95%A0%EC%9B%94%EB%8F%99%EB%AC%BC%EB%B3%91%EC%9B%90&amount=3300'
```

이렇게 얻은 문자열을 QR 이미지로 굽는다. 별도 의존성을 추가하지 않고 실행할 수 있다.

```bash
npx qrcode -o docs/demo/qr-payment-normal.png -w 512 "aewol://pay?merchant=%EC%95%A0%EC%9B%94%EB%8F%99%EB%AC%BC%EB%B3%91%EC%9B%90&amount=3300"
```

페이로드에 `&`가 들어가므로 **문자열 전체를 반드시 따옴표로 감싼다.** 감싸지 않으면 셸이
`&`를 명령 구분자로 해석해 `amount`가 누락된 QR이 만들어진다.

### 방법 B — 온라인 생성기

인코딩된 문자열(방법 A로 얻은 값)을 그대로 붙여넣는다. **인코딩 전 한글 문자열을 넣지 않는다.**

## 4. 시연 순서

사전 준비 — 백엔드·MySQL·Redis 기동, 시연 계정 로그인, 지갑 잔액이 3,300원 이상이고
1,500,000원 미만인지 확인.

1. 하단 네비 **결제** 탭으로 진입 (`/payment/qr`). 카메라 권한을 허용하면 스캔 화면이 뜬다
2. **정상 결제** — `qr-payment-normal.png`을 카메라에 비춘다
   → 가맹점명·금액·결제 후 잔액이 표시된 확인 화면
   → `결제하기` → 완료 화면에서 남은 잔액 확인
   → `거래 내역 보기`로 이동해 방금 결제가 기록됐는지 확인
3. **잔액 부족** — 다시 결제 화면으로 돌아와 `qr-payment-insufficient.png`을 스캔
   → 결제 버튼이 잠기고 `충전하러 가기` 버튼이 뜬다
4. **잘못된 QR** — `qr-payment-invalid.png`을 스캔
   → "애월 결제 QR이 아니에요" 안내가 뜨고 결제로 넘어가지 않는다

### 카메라 없이 시연할 때

QR 이미지를 시연 기기에 미리 저장해두고, 스캔 화면 아래 **사진에서 QR 불러오기** 버튼으로
같은 흐름을 그대로 보여줄 수 있다. 카메라를 못 쓰는 환경에서는 이쪽이 안전하다.

---

## 5. 알려진 제약

**카메라는 HTTPS 또는 localhost에서만 열린다.** `getUserMedia`가 secure context를 요구하기
때문이다. PC 브라우저에서 `http://localhost:5173`으로 시연하면 문제없지만, 실기기를 로컬 IP로
접속시키는 방식은 동작하지 않는다. 실기기 시연을 하려면 HTTPS 개발 서버 설정과 백엔드
CORS 허용 오리진 추가가 별도로 필요하다.

**QR에 금액이 그대로 들어 있어 위조가 가능하다.** 가맹점명과 금액을 QR에 직접 인코딩하는
방식을 택했기 때문에, 사용자가 QR을 새로 만들어 금액을 바꿀 수 있다. 시연 범위에서는 감수한
선택이며, 실서비스로 가려면 서버가 발급한 결제요청 ID만 QR에 담고 서버에서 금액을 조회하는
방식으로 바꿔야 한다. 선택 근거는 `src/utils/qr.js` 상단 주석에 남겨두었다.
